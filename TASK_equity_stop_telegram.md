Implement two safety/monitoring features in forex_live_bot_gold_cwider.py.
Context: this bot trades XAUUSD on a live Real Cent Exness account (small
capital, ~$218 equivalent) using the Hybrid Trend-Pullback strategy
(adx20tp7 and adx18tp7 variants only — m5tp7 has been permanently retired
due to poor live performance, do not touch anything related to it).

================================================================================
FEATURE 1 — Portfolio-level equity-stop circuit breaker
================================================================================

Problem: ForexConfig already has a `stop_equity_frac: float = 0.35` field,
but it is never referenced anywhere in the live bot loop. There is
currently NO automatic circuit breaker at the portfolio level — only
per-trade SL (which limits damage from a single position) and a manual
kill-switch file (which requires a human to act). A losing streak across
many trades (each hitting normal SL) can silently accumulate with nothing
to stop it.

Requirements:

1. Reuse the existing `stop_equity_frac: float = 0.35` field in
   ForexConfig (forex_config.py) — no new config field needed.

2. In forex_live_bot_gold_cwider.py, add a new file path `EQUITY_STOP_FILE`
   alongside the existing STOP_FILE/STATE_FILE/etc., generated by
   `_make_paths()`:
   - cwider variant: `EQUITY_STOP_{SYMBOL}`
   - other variants: `EQUITY_STOP_{SYMBOL}_{VARIANT}`
   Update all call sites that unpack `_make_paths()` (module-level init and
   inside `main()`) to include this new path.

3. In `GoldCWiderBot.__init__`, add:
   - `self.peak_equity: float = cfg.total_capital_usd`
   - `self.equity_stop_triggered: bool = False`

4. Add method `_check_equity_stop(self, equity: float)`:
   - Update `self.peak_equity = max(self.peak_equity, equity)`.
   - If `self.equity_stop_triggered` is already True, return immediately
     (latched — do not re-evaluate or re-trigger).
   - Compute `floor = self.peak_equity * (1 - cfg.stop_equity_frac)`.
   - If `equity <= floor`: set `self.equity_stop_triggered = True`, log a
     CRITICAL message with peak/current/drawdown%/threshold, and write
     `EQUITY_STOP_FILE` to disk with those details (peak_equity,
     equity_at_trigger, drawdown_pct, threshold_pct, timestamp, and a note
     that the file must be deleted manually to resume). Wrap the file write
     in try/except so a filesystem error never crashes the bot.
   - Also fire a Telegram alert here (see Feature 2) with the same details.

5. Call `self._check_equity_stop(equity)` inside `process_bar()`, right
   after computing `equity` and calling `_rollover_day()`.

6. In `process_bar()`'s kill-switch section, block new entries if EITHER
   the manual kill-switch file exists OR `EQUITY_STOP_FILE` exists OR
   `self.equity_stop_triggered` is True. Existing open positions continue
   to be managed normally (broker SL/TP, timeout) regardless — this only
   blocks opening NEW positions, exactly like the existing manual
   kill-switch behavior. Log a distinct WARNING line when equity-stop is
   the active block reason (separate from the existing kill-switch log
   line) so the two causes are distinguishable in the log.

7. Persistence across restarts: add `peak_equity` and
   `equity_stop_triggered` to the dict written by `save_state()` (under a
   new `"equity_stop_state"` key) and read them back in `load_state()`,
   defaulting to `cfg.total_capital_usd` / `False` if absent (for backward
   compatibility with old state files). If loaded as `True`, log a warning
   that the equity-stop remains latched until the file is deleted.

8. IMPORTANT — do NOT implement any auto-clear/auto-resume logic. This is
   intentional: once triggered, the block must persist until a human
   manually deletes `EQUITY_STOP_FILE`, even across bot restarts. The
   rationale (for anyone reviewing this code later): a 35% portfolio
   drawdown is a signal that something may be structurally wrong (regime
   shift, overfit strategy, a code bug) — not something the bot should be
   allowed to decide on its own is "fine now" just because equity ticked
   up slightly from an existing open position. Do not add a time-based or
   equity-recovery-based auto-clear even if it seems convenient.

9. Add a line to the startup banner (`_print_banner_and_verify_demo`)
   showing the threshold and instructions, e.g.:
   "Equity-stop   : 35% drawdown from peak -> touch EQUITY_STOP_XAUUSD_ADX20TP7
   auto-created, blocks NEW entries (delete file to resume)"

================================================================================
FEATURE 2 — Telegram alerts
================================================================================

Requirements:

1. Add `import urllib.parse` and `import urllib.request` at the top of
   forex_live_bot_gold_cwider.py. Do NOT add a dependency on the `requests`
   library — use only Python's standard library, since the VPS may not
   have `requests` installed.

2. Add method `_send_telegram_alert(self, message: str)` on
   `GoldCWiderBot`:
   - Read `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` from
     `os.environ` (populated via `.env` + `load_dotenv()`, which the file
     already calls in `main()`).
   - If either is missing, log at DEBUG level and return silently — do not
     error or warn (Telegram is optional/best-effort).
   - Otherwise POST to `https://api.telegram.org/bot{token}/sendMessage`
     with `chat_id` and `text` form-encoded via `urllib.parse.urlencode`,
     using `urllib.request.Request` + `urllib.request.urlopen(req,
     timeout=10)`.
   - Wrap the whole network call in try/except; on failure, log an ERROR
     but never raise — a Telegram outage must never crash or block the
     trading loop.

3. Call `_send_telegram_alert()` from these four places, each with a
   distinct emoji prefix and relevant details:
   a. Equity-stop trigger (inside `_check_equity_stop`, right after writing
      EQUITY_STOP_FILE): 🚨 emoji, include variant tag, symbol, peak
      equity, current equity, drawdown %, threshold %, and the instruction
      to delete the file to resume.
   b. New position opened (inside `_open_position`, right after the
      existing `[OPEN]` log line): 🟢 emoji, include variant tag, symbol,
      side, lot, entry price, SL, TP, spread, slippage.
   c. Position closed via bot-initiated timeout (inside `_close_timeout`,
      right after the existing `[CLOSE-TIMEOUT]` log line): ⏱️ emoji,
      include variant tag, symbol, side, lot, entry, fill price, net PnL.
   d. Position closed by broker SL/TP (inside `_log_broker_close`, right
      after the existing `[CLOSE-{reason}]` log line): use 🟢 if
      `net >= 0` else 🔴, include variant tag, symbol, side, lot, entry,
      fill price, net PnL, and whether it was SL or TP (the `reason`
      variable already computed in that method).

4. Add a line to the startup banner showing whether Telegram is configured,
   e.g.:
   "Telegram alert: configured ✅" if both env vars are set, else
   "Telegram alert: NOT configured ⚠️ (set TELEGRAM_BOT_TOKEN/TELEGRAM_CHAT_ID in .env)"
